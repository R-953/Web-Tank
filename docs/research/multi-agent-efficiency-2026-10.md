# 多智能体协作的 token 消耗与效率评估(截至 2026-10-02)

> 主程(Claude Code)根据会话记录和调度报告统计,回答一个问题:**同样的活,让 Claude 当中枢派给其他 agent,比 Claude 自己全做省多少 Claude 额度,代价是什么。**
> 统计脚本在主程会话的临时目录里,方法和口径写在第 5 节;所有「估计」都给了区间。

## 1. 结论

- **Claude 额度省了大约四分之三。** 第六到第九轮(B 段)落地约 1.85 万行,Claude 实际花了约 52 美元(按 API 价格折算,下同);如果全由 Claude 自己写,估计要 200–340 美元。把一次性的搭建成本(调度脚本 + 模型测试,约 23 美元)也算上,仍然省 63–78%。
- **按「每千行落地代码」算,Claude 的花费从约 19.5 美元降到约 2.8 美元,约为原来的七分之一。**
- **省下的部分由其他额度承担:** Antigravity 的 Gemini 3.8 Flash High 用了约 2.6 亿 token(九成以上是缓存读),约占每周限额的 29%,另外有几次接近五小时上限;Copilot 用了 8 次高级请求;第三方模型(Opus 4.6 等)只在模型测试时用过。
- **省时间:** agent 并行跑,B 段 agent 累计工作约 5.4 小时,实际等待约 1.7 小时。
- **代价是返工和审查:** 28 张派出去的卡,机器分全部满分,但主程审查后至少 8 张返工(约三成),包括两次编造出处(020、039)、几次外观问题(038、040、042)、两处逻辑遗漏(020、030)。审查的花费已经算在 Claude 的 52 美元里;**不审查就合并是不行的**。

## 3. 假设全部由 Claude 自己做(B 段)

用两种互相独立的方法估算 agent 写的约 15,700 行如果换成 Claude 写要花多少:

| 方法 | 做法 | 结果 |
|---|---|---|
| ① 按行折算 | A 段 Claude 自己做任务时,每千行约 19.5 美元(96 美元 / 4,900 行) | 15,700 行 × 19.5 ≈ **306 美元** |
| ② 按 token 折算 | 把 Flash 实际用的 token 按 Claude 的价格结构重算(输入算缓存写、缓存读、输出 + 思考各按相对价格) | ≈ **171 美元** |

两种方法互相印证:以 039 一张卡为例,方法 ② 算出约 14 美元(含返工),806 行,每千行约 17 美元,和 A 段的 19.5 美元很接近。

在这之上,Claude 自己做时仍然要和负责人讨论需求、做设计、自测(浏览器里看效果),这部分约等于现在主程花费里「非写卡、非审查他人」的那一半,约 25–35 美元。

| | Claude 花费 | 其他额度 |
|---|---|---|
| 全由 Claude 做(估计) | **约 200–340 美元**(中值约 260) | 无 |
| 多 agent 协作(实际) | **约 52 美元**(加上一次性搭建 23 美元为 75 美元) | Flash 约 2.6 亿 token(每周限额约 29%)+ Copilot 4 次 |
| Claude 节省 | **约 74–85%**(含搭建成本为 63–78%) | |

## 4. 质量与返工

| 项目 | 数字 |
|---|---|
| 派出去的卡 | 28 张(Flash 24、Copilot 4) |
| 机器分 | 全部 90 / 90(只查得到 lint / test / build、守规则、交付格式) |
| 主程审查后返工 | 至少 8 张:014、019、020、029 / 030、038、039、040、042 |
| 编造出处 | 2 次(020 的库宾卡实测、039 的俄文维基条目和 APP-6D 章节号) |
| 只在浏览器里才看得出的问题 | 038 徽标重叠,040 国旗和卡片排版,042 地图被裁掉 |

**经验:**
- 机器分满分只说明「能编译、测试过、守格式」,不说明对不对、好不好看。界面类的卡一定要在浏览器里看。
- 带出处的产出必须逐条点开核实。核实后把正确出处和原文要点写进返工消息,一次就能改对。
- 返工用「续跑原对话」(`agy --conversation`)最省:agent 不用重新读代码,主程只写差异。
- 小而边界清楚的卡派 Copilot 很划算:一次请求、几分钟、一次过。

## 5. 方法与口径

- **Claude 的花费:**
  - 总数取自 Claude Code 写在会话记录(`~/.claude/projects/*/*.jsonl`)里的累计花费 `cost-state.totalCostUSD`,是按 API 单价折算的金额。负责人用的是订阅额度,这个金额只用来做相对比较。
  - 阶段切分:逐条读会话记录里的每条模型回复,按 `message.id` 去重(同一条回复在多行或多个文件里出现时,各字段取最大值)。每条回复按相对单价算权重:非缓存输入 1、5 分钟缓存写 1.25、1 小时缓存写 2、缓存读 0.1、输出 5。按时间窗口求和,再按总金额等比例分摊。
  - 会话记录里没有后台调用(上下文压缩、会话标题等),这部分随比例一起分摊。
- **行数:**
  - 按非合并提交的增删行数统计,不含 `package-lock.json` 和图片。
  - A 段剔除了 09-29 补提交的第五轮成果(1 万多行,是这些会话之前做的)。
  - B 段按提交里有没有 Claude 的署名区分作者,主程续跑 agent 后代提交的返工代码(约 1,800 行)算 agent 的。
- **agent 用量:**取自 `Archive/agent-runs/*/` 下每次调用的日志(Antigravity 输出的 JSON 用量)和 `report.json`。Copilot 不报告 token,只记高级请求次数。
- **主要误差来源:**
  - A 段包含了初次熟悉代码库和定协作规则的成本,可能高估了 Claude 每千行的花费。所以方法 ① 偏高,方法 ② 偏低(Flash 有不少「等 npm test 跑完」的空转轮次,Claude 一般更省)。真实值大概率在两者之间。
  - B 段里有些行(三维模型的几何数据、日志汇总)每行成本低于一般逻辑代码。
  - 本报告只统计到第九轮第一波合并(2026-10-02),不含本次写报告的会话。

## 6. 建议

1. 继续用「Claude 写卡 + 审查,Flash 写代码」的分工。按目前的比例,Claude 额度大约能多撑四倍。
2. Flash 的五小时上限是现在的瓶颈:一轮四张大卡加返工就接近用满。大轮次可以拆成两波,中间隔开;或者把一部分卡派给 Opus 4.6(第三方额度,另算)。
3. 返工率约三成,主要集中在「要出处」和「看外观」两类卡。这两类卡上写清楚验收方式(给出已核实的出处、写明要在哪些窗口尺寸下看),能少返工一轮。
4. 每轮把调度报告的用量汇总进这份文档,方便以后对比。
