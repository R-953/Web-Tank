## 目标

弄清负责人这台笔记本(Windows 11、16 GB 内存,显卡以实测为准)上的真实帧率,决定植被和画质预设要不要优化。云端测试只有软件渲染(1–4 FPS),量不出真实帧率。

## 步骤

1. `npm ci`,然后 `npm run dev`,浏览器打开终端里显示的地址,加上 `?debug`。
2. 设置 → 游戏:打开「显示帧率」。
3. 在画质预设 **低 / 中 / 高** 下各测一遍,每一遍测三个场景:
   - A:河谷试验场出生点,静止 10 秒,读左上角的帧率;
   - B:向西开进出生点旁边的树林,边开边看 15 秒,记录最低和平均帧率;
   - C:开镜(Shift),5× 倍率看向北边,静止 10 秒。
4. 记录浏览器版本和显卡型号(地址栏打开 `chrome://gpu`,找 GL_RENDERER 一行)。
5. 每个预设在场景 B 截一张图。

## 结果(完成后填写)

- 新增文件:`docs/perf/2026-09-baseline.md`(环境、方法、结果表、结论)、`docs/images/perf-low.png` / `perf-medium.png` / `perf-high.png`(640 × 340,238–275 KB)
- 显卡 Intel UHD Graphics(核显,0xA7A8),Chrome 156。机器空闲时,平均帧率 A / B / C:低 59.9 / 59.9 / 60.0,中 57.9 / 55.4 / 59.9,高 51.3 / 44.8 / 57.7;场景 B 每秒最低:低 59、中 52、高 42。结论:三档都流畅,瓶颈在核显渲染不在 CPU,植被和画质预设暂时不用优化
- 没有改动 `src/`、`tests/`;没有跑 `npm test`(本卡只加文档和图片)
- 和任务卡不一致的地方:
  - 帧率不是读左上角,而是在页面里记录每帧间隔算出来的(左上角是滑动平均,也打开了,截图里能看到)
  - Chrome 扩展拿不到鼠标锁定,在页面里伪造了锁定状态,用脚本发键盘事件开车、开镜;场景 B 先用 `__debug.advance` 快进到树林边,再实时边开边测 15 秒
  - 显卡型号是用 `WEBGL_debug_renderer_info` 读的,没有打开 `chrome://gpu`(在游戏页面里直接读更省事),内容就是 GL_RENDERER 那一行
- 需要负责人知道的:
  - 后台同时跑 `tsc` / Vitest 时帧率会减半(11–33),这几轮数据没有计入结果表,报告里单独写了
  - 顺带发现一个 bug:给「重新开始本局」绑键后,按一下会每帧都重开一局(`src/main.ts` 重开后 `return` 前漏了 `input.endFrame()`)。建议开卡修复
